# Домашняя рабочая область

`GET /api/v1/workbench/` объединяет текущий профиль и несколько предметных проекций. Это read API для домашней страницы сотрудника, руководителя и HR. Данные принадлежат исходным модулям; отдельная таблица универсальных задач не создаётся.

## Контракт

| Поле | Смысл |
| --- | --- |
| `employee`, `leave` | Собственный профиль, официальный остаток и проекция портала |
| `learning_summary` | Только свои назначения, даже для менеджера и HR |
| `returned_requests` | Собственные заявления, требующие исправления |
| `draft_requests` | Собственные сохранённые черновики |
| `requests_to_review` | Заявки, которые текущий пользователь вправе рассмотреть на текущем этапе |
| `waiting_request_count` | Собственные заявления в ожидании руководителя или HR |
| `learning_outstanding` | Незавершённые назначения с доступным опубликованным курсом |
| `unavailable_learning_count` | Незавершённые назначения с недоступным курсом; историю не теряем |
| `open_knowledge_cases` | Собственные обращения или очередь своего юрлица для HR |
| `knowledge_case_purpose` | `track_own` для отслеживания, `hr_response` для ответа HR |
| `unread_notification_count` | Непрочитанные события текущего пользователя |

Каждый preview содержит полный `count` и первые `results`. `preview_limit` по умолчанию 5, допустимы 1–20. Списки возвращают существующие сериализаторы запросов, назначений и обращений. Дизайн-агент не пишет новую параллельную схему карточки.

Полный список открывается через соответствующий предметный endpoint с фильтрами. Не показывать `results.length` как общий объём и не загружать остальные страницы из других областей доступа.

## Объяснимый порядок

Возвращённые заявления сортируются от давно ожидающих исправления. Черновики — от давно созданных. Решения — от давно отправленных. Обучение — сначала просроченное, затем остальное обязательное, затем рекомендованное; внутри группы ближайший срок, после него назначения без срока. Обращения HR — от давно созданных. UUID завершает порядок при равенстве дат.

Это выбранная политика отображения, не AI-оценка важности и не официальный SLA Jana Post. Предметный экран сохраняет право человека выбрать другую разрешённую сортировку.

## Доступ и свежесть

Сервер требует активный профиль. Параметр для произвольного сотрудника не предусмотрен. Заявки на согласование фильтруются по текущему этапу, назначенному руководителю и текущей области доступа. Самосогласование не предлагается. Каждый результат дополнительно содержит фактические `allowed_actions`; команда повторно проверяет права и версию.

`computed_at` обозначает время сборки ответа. Это составное read view с обычной изоляцией PostgreSQL, не строгий исторический снимок всех таблиц. Конкурентное изменение возможно после ответа; перед записью действует optimistic version предметного агрегата.

Уведомление описывает событие. Работа на домашней странице описывает текущее состояние. Прочтение уведомления не меняет ни один из предметных preview. После команды frontend инвалидирует workbench и затронутые списки; при возврате фокуса обновляет данные.

Universal inbox с назначением произвольных задач, сохранёнными server views, snooze и массовыми решениями остаётся отдельным продуктовым расширением. Этот endpoint уже даёт общее место для существующих процессов, не вводя неподтверждённую вторую state machine.
