# Keyboard navigation on the integrated application

18 October 2026. Scope is the loaded normal state of S01–S31, a narrow navigation disclosure and an employee advance journey. This is an owner check, not independent release acceptance or a screen-reader audit.

| Severity | Location | Before | After | Why |
| --- | --- | --- | --- | --- |
| MEDIUM | `AppShell` in `frontend/src/app.tsx` | Escape leaves narrow navigation open and focus stays inside it. The native button toggles it, but there is no dismissal handler. | Escape on the trigger or inside navigation closes the disclosure and focuses its trigger. Following a link still closes navigation and moves focus to the new main region. | Follow the W3C disclosure-navigation mechanism while preserving ordinary links and Tab order. The menu RED is `.artifacts/keyboard-baseline-20261018-1.log`. The navigation remains present after Escape. The same run also exposes two verification mistakes, retained rather than represented as product defects. Native calendar-button focus does not make the outer input match `:focus-visible`, although the screenshot shows the browser's indicator. The first attempted date-entry sequence also uses the wrong segment order for this Chrome build.

Calibration is `.artifacts/keyboard-date-calibration-20261018-1.log` and its `captures/date-keyboard-*.json`. Three actual screenshots were opened, including the internal calendar focus and the successful date entry. This Chrome for Testing displays `mm/dd/yyyy` despite the configured context locale. Typing month `01`, day `15` and year `2027` without extra arrows produces the live ISO value `2027-01-15`. The failed day-first and Tab-between-segments attempts remain in the calibration evidence. [MDN explains the native control's browser-dependent display and ISO value](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/date).

`tests/keyboard/focus.ts` records actual Tab stops, focus selectors, outlines and visible hit points. It reads labels as hints rather than pretending to implement the accessible-name algorithm. Native date segments can repeat one element path. The test accepts focus-within only for native date and date-time controls and still requires an actual outer outline and an exposed hit point. It does not waive missing focus for other controls.

It is not a count of unique controls. The raw observations and summary are `.artifacts/browser/keyboard-green-20261018-1/captures/` and `.artifacts/keyboard-normal-summary-20261018.json`.

The W3C [disclosure navigation example](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/) supplies the established mechanism. It was studied, not copied as a new component dependency. Fstack's original Jakub accessibility skill keeps native elements, ordinary navigation semantics and focus restoration. Emil's rules keep keyboard actions stationary. Fix Root Causes places the Escape handler at the disclosure owner. Model the Domain retains the existing local open state and one trigger reference. The typed recorder is a reusable check over the existing screen manifest rather than another screen registry.

The material risk is confusing native shadow-control focus with a missing indicator. Actual calibration images and the scoped composite rule check that distinction. The automated tour does not prove focus aesthetics, every pointer interaction by keyboard, radio-arrow behavior, all loading/error/pending states, screen readers, other engines or physical devices. Those remain separate checks. Whole-interface acceptance stays open.
