# Jana Academy: реализованный контракт и проверка

Состояние на 17 октября 2026 года. Модуль реализован в `backend/apps/academy`. Backend использует Django, DRF и общие механизмы сессии, CSRF, области сотрудников, событий, уведомлений и идемпотентных команд. Frontend этим модулем не создаётся.

## Подтверждённый результат

В изолированной PostgreSQL 16.15 выполнены 25 тестов Academy. Все 25 прошли. Четыре проверки запускают конкурентные HTTP-команды через отдельные соединения с базой. Выполнены реальные команды миграции, наполнения и чтения отчёта.

| Схема | Ноль ошибок и предупреждений при проверке с общим согласованным `LanguageEnum` | `drf-spectacular`, проверка ниже |

Изолированная ветка не меняет глобальный `config/settings.py`. Для проверки схемы в процесс проверки передан `ENUM_NAME_OVERRIDES = {"LanguageEnum": [("ru", "Русский"), ("kk", "Қазақша")]}`. Родительский агент объединяет эту настройку с модулем Knowledge. Без неё базовая настройка ветки даёт одно предупреждение о двух именах одного набора языков. Ошибок генерации нет. Итоговая объединённая конфигурация требует повторного запуска `--fail-on-warn`.

## Модель и ответственность

`Course` принадлежит юридическому лицу и содержит редактируемый черновик, доступность, оптимистическую `version` и ссылку на текущую публикацию. Создатель записан в `owner`. Другие разрешённые HR того же юридического лица могут работать с этим организационным содержанием. Технический superuser имеет явно отдельную область администрирования.

`CourseVersion` сохраняет название, описания, категорию, язык, порядок уроков, вопросы, ключи, объяснения, порог и предел попыток. Версия наследует общий `AppendOnlyModel`. Обычное сохранение, обновление через его queryset и удаление запрещены. Защита относится к приложению и его ORM. Прямой доступ привилегированного оператора к SQL не объявляется проверенной границей этого модуля.

`Enrollment` связывает сотрудника с фиксированной версией. Пара сотрудник и версия уникальна в базе. `LessonCompletion` и `QuizAttempt` сохраняют отдельные факты. Опубликованный вопрос не извлекается из текущего черновика при оценке старого назначения.

| Рассмотренная форма | Следствие | Решение |
| --- | --- | --- |
| Отдельные изменяемые строки уроков и вопросов | Для сохранения старых результатов потребовалась бы отдельная версия каждой связи и строгая координация редакторов | Не выбрана |
| Неизменяемый snapshot версии с типизированной границей DRF | Назначение ссылается на один целостный опубликованный набор. Одна транзакция публикует материал | Реализована |

Это локальное сравнение двух форм. Отдельная параллельная панель архитекторов этого модуля не запускалась, поскольку все четыре доступных слота команды были заняты. Независимое принятие кода и окончательная интеграционная проверка принадлежат родительскому агенту.

Изменения выполняют функции `services.py`. Команда сначала проверяет текущую область, затем проходит через общий `core.idempotency.execute`. Одинаковый ключ и payload возвращают сохранённый результат. Другой payload с прежним ключом получает `409`. Результат не возвращается из кеша до повторной проверки актуального доступа.

Назначение блокирует курс и сотрудника на время проверки уникальности. Изменение прогресса блокирует назначение. Такая блокировка сериализует версии, счётчик попыток и итоговое завершение. Запись результата, событие и уведомление находятся в одной транзакции. Уведомление создаётся при назначении и при успешном завершении курса.

## Доступные HTTP-маршруты

Все пути начинаются с `/api/v1/`. POST-команды требуют сессию, CSRF и заголовок `Idempotency-Key`. Команды существующего курса или назначения также принимают `expected_version`.

| Метод и путь | Назначение | Ответ |
| --- | --- | --- |
| `GET academy/courses/` | Каталог опубликованных курсов текущей области | Пагинация и метаданные без уроков и вопросов |
| `GET academy/courses/{id}/` | Метаданные текущей публикации | `CatalogCourse` |
| `GET academy/manage/courses/` | Реестр HR, включая черновики и архив | Краткие авторские метаданные |
| `POST academy/manage/courses/` | Создание курса с `slug`, `draft` и необязательным разрешённым `legal_entity` | Авторская деталь |
| `GET academy/manage/courses/{id}/` | Текущий черновик HR, включая серверные ключи | Авторская деталь |
| `POST academy/manage/courses/{id}/save-draft/` | Сохранение целого типизированного `draft` | Авторская деталь и новая версия записи |
| `POST academy/manage/courses/{id}/publish/` | Публикация новой неизменяемой версии | Авторская деталь |
| `POST academy/manage/courses/{id}/archive/` | Отключение новых назначений и прогресса | Авторская деталь |
| `POST academy/manage/courses/{id}/restore/` | Возврат доступности уже опубликованного курса | Авторская деталь |
| `GET academy/manage/courses/{id}/revisions/` | Разрешённая история публикаций HR | Пагинация авторских версий |
| `GET academy/enrollments/` | Собственные или разрешённые командные назначения | Пагинация и производные состояния |
| `POST academy/enrollments/` | Назначение HR по `employee`, `course_version`, `required`, `due_at` | Новое назначение |
| `GET academy/enrollments/{id}/` | Метаданные, уроки по факту завершения и история результатов | `EnrollmentDetail` |
| `POST academy/enrollments/{id}/start/` | Явное начало владельцем | Обновлённое назначение |
| `POST academy/enrollments/{id}/complete-lesson/` | Подтверждение указанного `lesson_id` владельцем | Обновлённое назначение |
| `GET academy/enrollments/{id}/learning/` | Уроки и вопросы закреплённой версии для владельца | Материал без ключей |
| `POST academy/enrollments/{id}/submit-attempt/` | Сдача `answers` владельцем | Попытка и обновлённое назначение |
| `GET academy/enrollments/{id}/attempts/` | Разрешённые результаты и выбранные ответы | Пагинация без ключей |
| `GET academy/enrollments/summary/` | Итоги той же разрешённой отфильтрованной выборки | Числа с областью и временем расчёта |

Каталог поддерживает `category`, `language`, `search` и разрешённую сортировку. Назначения поддерживают `employee`, `required`, `completion_state`, `overdue`, `has_failed_attempt`, `category`, `course`, `due_before`, `due_after`, поиск и сортировку. Список и сводка используют одинаковые фильтры. Точные поля и параметры описывает генерируемый OpenAPI, который остаётся источником типов frontend.

## Контракт домашнего экрана

`selectors.visible_enrollments(user)` возвращает разрешённую выборку с материалом версии, сотрудником, попытками, завершениями уроков и признаком `has_failed_attempt`. Историческое содержание другой текущей юридической области скрывается после перевода сотрудника. Записи сохраняются для разрешённого технического администрирования.

`selectors.enrollment_summary(queryset, *, now=None, scope="visible_enrollments_with_current_filters")` принимает эту выборку с дополнительными фильтрами. Родительский домашний экран использует один момент `now` для своих разделов и `scope="self"` для личного обучения.

Сводка возвращает `scope`, `computed_at`, `total`, `completed`, `in_progress`, `not_started`, `overdue`, `required_outstanding`, `has_failed_attempt`, `due_next_seven_days`, `completion_percent`. При пустой выборке процент равен `null`. JSON-ответ сериализует процент как десятичную строку с двумя знаками.

`material_progress` считает долю подтверждённых обязательных уроков. Он не означает успешную сдачу. `completion_state` имеет значения `not_started`, `in_progress`, `completed`. Просрочка является независимым признаком незавершённого назначения. Архив меняет доступность и команды, но не стирает результат. `allowed_actions` вычисляет сервер для владельца и текущего состояния.

## Фактический учебный набор

Команда `python manage.py academy_report` прочитала следующий результат после выполнения миграций и реального `seed_demo` в изолированной базе. Сведения о людях, курсах и правилах синтетические.

| Объект | Количество |
| --- | ---: |
| Канонические курсы | 30 |
| Опубликованные версии при первом наполнении | 30 |
| Отдельные уроки | 60 |
| Различные вопросы | 90 |
| Слова материала, `body_markdown.split()` | 12 670 |
| Слова на курс с пометкой демо | 407–441 |
| Назначения | 189 |
| Сотрудники с назначениями | 29 |
| Сохранённые попытки | 94 |

Каталог принадлежит синтетическому юрлицу A. Юрлицо B не получает его содержание автоматически. Это явная граница доступа, а не объединение персонала компаний. Модуль поддерживает создание отдельного каталога HR второй организации через те же API.

Дане назначены 24 курса. Из них 8 завершены, 6 начаты и 10 не начаты. Пять незавершённых назначений просрочены. Четыре других имеют срок в следующие семь дней на момент первого наполнения. Восемнадцать назначений обязательны, шесть рекомендованы. У трёх завершённых курсов сохранена прежняя неудача, у двух начатых есть текущая неудачная попытка. У нового сотрудника три назначения без начала. Остальные 27 сотрудников первой организации имеют по шесть назначений.

Сроки отсчитываются от первого наполнения. Повтор seed сохраняет реальные последующие изменения и не двигает срок ради постоянной демонстрационной цифры. Интерфейс читает текущие серверные количества. Они не записываются константами в экран.

Все 30 курсов имеют казахское название. Материалы, вопросы и краткие описания пока русские. Полный казахский перевод и его редакторская проверка не заявлены. Учебные ключи присутствуют в открытом исходном коде seed. Набор предназначен для демонстрации LMS, а не для защищённой аттестации реальных сотрудников.

## Воспроизводимые команды

Команды запускаются из `backend` с настроенной `DATABASE_URL` для отдельной PostgreSQL-базы.

```bash
uv sync --frozen
uv run python manage.py migrate --noinput
uv run python manage.py seed_demo --skip-requests --skip-knowledge
uv run python manage.py academy_report
uv run pytest apps/academy -q
uv run ruff check apps/academy
uv run python manage.py makemigrations --check --dry-run
uv run python manage.py spectacular --file /tmp/academy-openapi.yaml --validate --fail-on-warn
```

Локальный каталог `.venv` также позволяет выполнить те же команды через `.venv/bin/python`, `.venv/bin/pytest` и `.venv/bin/ruff`. Эта форма использована в текущей среде после установки lockfile. Секреты тестовых аккаунтов создаёт общий `seed_demo` в отдельном файле credentials. Они не включены в данный документ или исходный код.

## Применённые навыки и границы проверки

| Навык | Конкретное влияние |
| --- | --- |
| Pstack `poteto-mode` и Codex mapping | Изолированная ветка реализации. Общий контракт прочитан до изменения. Проверки выполняются реальными доступными инструментами |
| `how` и `architect` | Область сотрудника, события, уведомления и команды оставлены общим модулям. Academy владеет только своим учебным состоянием |
| `principle-model-the-domain` | Доступность, версия, назначение, урок и попытка имеют отдельное представление |
| `principle-type-system-discipline` | Вложенные входы проверяют DRF serializers. Схема генерируется из них. Ручной альтернативный контракт TypeScript не создан |
| `principle-make-operations-idempotent` | Повтор команды восстанавливает один результат. Повтор seed сохраняет живые изменения |
| `principle-test-behavior-not-implementation` | Тесты выполняют API-команды, проверяют доступные записи, результат, историю и отсутствие дубликатов |
| `fstack`, Emil `emil-design-eng` | Результат сохранения представлен серверным состоянием. Pending в будущем интерфейсе не должен подменять подтверждение |
| Jakub `better-interface`, `better-writing` | Состояния различимы по значениям и смыслу. Ошибки называют восстановление. Русский материал не выдаётся за полный KZ-перевод |
| `technical-writing`, `unslop`, `deslop` | Термины совпадают с кодом. Удалены лишние слои и комментарии. Проверка не объявляется испытанием несуществующих экранов |

Навык `state-machine` прочитан для понимания реальных состояний. Его страница визуальной проверки не запускается, поскольку frontend принадлежит следующему агенту. `no-comments` требует независимого читателя. Внутри этого агента свободного слота для него нет. Единственный комментарий Python в модуле создан генератором миграции. Независимая проверка остаётся у родительского агента и не заменяется авторским просмотром.

Не выполнены браузерная доступность, мобильная проверка, тест финального контейнера и независимая редактура казахских названий. В Academy нет сохранения несданных ответов на сервере, таймера экзамена, загрузки SCORM, сброса попыток, самостоятельной записи сотрудника и автоматических кадровых решений. UI не должен показывать команды, которых нет в OpenAPI. После исчерпания попыток материал и результаты остаются видимыми. Дополнительное обучение требует осмысленного действия HR по поддерживаемому процессу новой версии и назначения.

`body_markdown` является содержанием HR. Будущий frontend обрабатывает его как недоверенный текст и использует Markdown renderer с выключенным произвольным HTML или проверенной очисткой. Backend не выдаёт HTML-страницы материала и не заявляет выполненную браузерную проверку этого отображения.
