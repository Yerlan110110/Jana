# Keyboard and button feedback checkpoint

18 October 2026. Scope is the shared JanaMen action adapter on the actual assistant entry. This is not an inventory-wide keyboard or motion verdict.

| Before | After | Why |
| --- | --- | --- |
| Space activates the shared scale transition. The upstream active-state `translate` also moves the button down by 1px. That translation survives the existing reduced-motion rule. | The adapter removes the inherited translation. Scale runs only without a reduced-motion preference and outside keyboard-visible focus. | Keyboard and reduced-motion activation keep the control stationary. The fix belongs to the adapter, not one button label. |
| Focused buttons stop their transition, but a button that loses focus resumes the upstream border and shadow transition. Rapid Tab leaves several fading focus rings. | The adapter transitions only `transform`. Focus, borders, colors and shadows change immediately. | The actual focused control remains clear during keyboard navigation. Deleting the extra transitions also avoids their paint cost. |
| Press values and timing are duplicated in the application rule. | Project tokens supply scale `0.96`, a 150ms press, a 100ms release and `cubic-bezier(0.23, 1, 0.32, 1)`. | Jakub's exact press recipe fits Emil's permitted scale and duration ranges. Emil supplies the strong curve, immediate keyboard behavior and shorter response. No motion library or input-modality state is added. |

The actual RED is `.artifacts/button-motion-red-20261018-2.log`. It records a 1px translation in both normal and reduced motion, a transform on keyboard activation and running keyboard transitions. The earlier first attempt also demanded a literal zero duration. Pace deliberately reports a 0.001ms duration under reduced motion. That number is diagnostic, not a visible defect. The corrected oracle checks running animations and movement, and still fails on the original behavior before the repair.

The first repaired run exposed a fixture assumption. Chrome retains keyboard-visible focus when a pointer presses the same already-focused button. The pointer check now uses another real suggestion, asserts pointer-visible focus is false and checks its actual result. Keyboard focus remains an automatic static-motion case. There is no artificial blur or input-state injection.

The first video then revealed fading old focus rings. Selected decoded frames show the earlier logout ring while another control is focused. A new regression reproduces four blurred buttons still animating at `.artifacts/button-focus-release-red-20261018-1.log`. Limiting the adapter to transform repairs that class of focus transition. No upstream component or broad reduced-motion override is changed.

The final run passes three tests including employee setup at `.artifacts/button-motion-final-20261018.log`. It tabs to a real suggestion, holds Space, reads the actual transform, translation, focus outline and animation state, releases Space and checks the resulting question. It separately presses another real suggestion with the pointer, waits for the actual CSS animation to finish and verifies the scale and return. It repeats under the browser's reduced-motion media setting. It does not send an assistant request or modify business records.
