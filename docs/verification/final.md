## Что именно проверяет живой HTTP-прогон

API работал под Gunicorn с двумя workers, PostgreSQL и отдельным `process_outbox --watch`. Runner использовал Python standard library, самостоятельные cookie jars сотрудников, руководителя и HR, реальную CSRF-защиту и только loopback origin.

Оба типа заявления прошли создание, редактирование, отправку, возврат руководителем, исправление, повторную отправку и согласование руководителем/HR. Проверялись неизменяемые версии, история, конфликт версии, повтор с тем же ключом, конфликтующее повторное использование ключа, попытки самосогласования и доступ другого юрлица.

Academy-сценарий создал свой отдельный курс, опубликовал и назначил его, подтвердил материалы, сохранил неудачную и успешную попытку. Сервер отверг клиентский балл; ключи отсутствовали в learner-ответах. Новая публикация и архив сохранили исходную версию и завершённый результат назначения.

Workbench сравнивался с полностью прочитанными разрешёнными реестрами. Worker сохранил mock-квитанции для утверждённых версий. Официальный остаток отпуска остался `24.00`; прогноз основного сотрудника изменился `18.00 → 17.00 → 16.00` после двух новых однодневных заявлений. Доставка документа не списала официальный остаток.

807 — число вычисленных утверждений одного runner, включая повторную проверку ответов. Оно не равно числу независимых тестов или бизнес-сценариев. Оба прогона предшествовали финальным исправлениям обработки ошибочных аргументов и cleanup самого runner; эти изменения прошли отдельное независимое ревью. Полный изменяющий данные сценарий после исправлений не повторялся.

Проверки отказа намеренно отправляют недопустимые изменения в синтетический API. Поэтому runner предназначен для отдельной демосреды: при дефекте проверяемого backend отказ может не сработать. Его обещание сохранения fixture относится к корректно работающему серверу.

## Набор данных и границы его смысла

В свежем наборе 30 различных курсов содержат 60 уроков, 90 вопросов и 12 702 слова учебного материала. Есть 189 назначений и 94 попытки. Дана имеет 24 назначения: 8 завершённых, 6 начатых и 10 новых; 5 просроченных и 4 со сроком в следующие семь дней. Эти количества относятся к моменту наполнения. UI читает текущий серверный результат.

Во всех курсах есть казахское название; уроки, вопросы и краткие описания русские. Полная локализация Academy не заявляется. 36 документов знаний и 6 обращений HR также синтетические. 3 миллиона клиентов из brief не используются как количество сотрудников компании.

Опубликованный набор поиска участвовал в настройке порогов. Результат 20/20 не является независимой оценкой качества на реальных вопросах. Следующий агент должен создать held-out набор, проверить перефразирование RU/KZ и выполнить оценку с реальным провайдером.

## Найденные ошибки и принятые исправления

Независимые проверки закрыли доступ деактивированного сотрудника через существующую сессию, пропущенный CORS-заголовок команд, передачу provider selector в Compose, переполнение поля дней отпуска, гонку области при назначении курса и различимые ответы фильтра на скрытый UUID. TM-03/TM-04 отредактированы для нетехнического сотрудника.

Полный seed выявил сериализацию `datetime` в манифесте; используется `DjangoJSONEncoder` и проверяется весь записанный JSON. Login явно возвращает 401 для неверных credentials и сохраняет 403 для CSRF. Тестовый cache очищается между независимыми случаями, а реальный лимит входа остаётся включённым и проверяется внутри одного случая.

В ходе общего прогона один seed-запрос при пустой статистике PostgreSQL выбрал крайне медленный план шести соединённых таблиц. Проверка полного наполнения и повторения заняла 897,67 секунды. Ограниченные выборки по UUID сохранили предметный результат; та же проверка заняла 28,68 секунды в финальном прогоне. Это наблюдение данной среды, не производственный benchmark. Тест теперь ограничивает отдельное SQL-выражение десятью секундами.

Схема истории первоначально зависела от SQLite/PostgreSQL из-за выведенных integer-ограничений. История и отправленные версии явно объявлены read-only; контракт одинаков на обеих базах. В HTTP-runner исправлены перезапись credentials через ошибочный output-path и выход необработанного исключения при cleanup. Исходные находки сохранены в [реестре ревью](reviews/README.md).

## Воспроизведение

Команды установки и выбора базы находятся в [README](../../README.md). Из `backend` с отдельной PostgreSQL:

```bash
uv run --env-file ../.env --frozen pytest -q --durations=10
uv run --env-file ../.env --frozen ruff check .
uv run --env-file ../.env --frozen python manage.py makemigrations --check --dry-run
```

Из корня репозитория:

```bash
npm ci --ignore-scripts --no-audit --no-fund
npm run contracts:check
node scripts/tooling/verify-skills.mjs
python3 -m unittest discover -s scripts/verification/tests -v
```

Готовые HTTP-команды, изменение синтетического набора и ограничения описаны в [scripts/verification](../../scripts/verification/README.md). Повторный seed сохраняет изменённые записи; он не служит командой reset.
