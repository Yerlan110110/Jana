# Pace и Jana Post для дизайн-системы JanaMen

Исследование от 17 октября 2026 года. Этот документ объясняет выбор дизайн-системы и границы повторного использования. Реализацию интерфейса выполняет следующий агент. Источники, измерения и результат REA находятся в [папке evidence](../design/evidence/pace-jana/README.md).

## Рекомендация

Выбрать Pace как предпочтительную основу согласованных компонентов и правил их применения. Фирменную палитру и язык продукта взять у Jana Post. Рабочие сценарии построить по исследованиям профессиональных HR и LMS продуктов из [product-rea.md](product-rea.md), с привязкой к реальному API JanaMen.

Это три самостоятельных решения. Компонентная система задаёт, как выглядят и работают повторяющиеся элементы. Jana Post задаёт принадлежность продукта компании. Кадровая модель задаёт, что сотрудник видит, понимает и может сделать.

Установку Pace нужно начать с проверки соответствия исходников публичному демо. В ходе исследования обнаружено существенное расхождение версий. Перенос всего каталога без этой проверки не даёт воспроизводимого результата.

Моя рекомендация для пользователя звучит так: **Pace с адаптацией под Jana подходит. Одной перекраски недостаточно. Главное отличие JanaMen должно быть видно в завершённых рабочих сценариях и объяснимых состояниях.**

## Какой именно Pace исследован

Пользователь указал [pace-ui.vercel.app](https://pace-ui.vercel.app/). Этот сайт ссылается на [yqecea/pace](https://github.com/yqecea/pace). Это отдельный проект, который нельзя подменять коммерческим продуктом `paceui.com` или его каталогами в поисковой выдаче.

Публичный сайт описывает систему ролей компонентов, единые токены, набор именованных пружин анимации и установку с квитанциями происхождения файлов. Эти заявления полезны как направление, но не заменяют проверку фактического установщика.

Через разрешённое соединение GitHub прочитан приватный репозиторий `yqecea/pace`. Исследованная ветка `main` указывает на коммит `fa7401f5adf36a073d3126e6baebce31d92bcb89`. Приватный исходный код в Jana не скопирован.

| Предмет проверки | Публичное развёртывание | Прочитанный `main` | Следствие |
| --- | --- | --- | --- |
| Набор установщика | Заявлены 44 компонента | `kit/manifest.json` содержит 21 запись файлов | Числа описывают разные версии или разные наборы |
| Реестр | Заявлены 369 записей | `kit/registry.json` содержит 20 записей | Каталог демо нельзя считать экспортируемым комплектом |
| Проверка использования | Сайт показывает `check-usage` | В `bin/pace.mjs` команды `check-usage` нет | Нельзя обещать такую проверку после установки этой ветки |
| Команды CLI | На сайте показаны короткие примеры с путём | Код принимает `doctor`, `plan`, `apply`, `verify`, `rollback` с собственным разбором аргументов | Команды нужно брать из выбранной версии CLI |
| Источники | Страница `/sources` перечисляет дополнительные источники и другие пины | `upstream-lock.json` содержит четыре исходных репозитория | Нужна связь конкретного развёртывания с коммитом |
| Основа компонентов | DOM публичного демо содержит маркеры `base-ui` | Манифест прочитанного комплекта содержит `radix-ui` | Маркер в DOM не доказывает происхождение всех компонентов |

Ссылки для проверки доступны в [source-provenance.json](../design/evidence/pace-jana/source-provenance.json). Приведённые числа получены из разных названных источников. Они не означают, что в Pace потеряны компоненты. Причина расхождения пока не установлена.

## Что подтвердил REA

Выполнена попытка открыть публичную страницу `/design` через REA 6.5.0. Навигация завершилась ошибкой до получения начального состояния. Инструмент указал, что повтор неизменённого запроса не поможет. Браузер, запущенный провайдером, был закрыт.

Затем выполнено контролируемое локальное воспроизведение публично выданной страницы. Исходные байты HTML не изменялись. Под исходными путями размещены 35 объявленных статических ресурсов. Все 35 ресурсов успешно скачаны, общий объём составил 1 910 036 байт. Это ресурсы публичного развёртывания, а не файлы приватного репозитория.

REA запустил Chromium 155.0.8059.84, открыл локальную страницу, дождался видимого `h1` и сохранил DOM и дерево доступности. Идентификатор результата: `ev_ccf7f31c9583359e00f3381ff31cce2120a395afd227915b09552210676648fd`. Браузер и собственный локальный сервер закрыты после исследования.

Полученные данные подтверждают наличие разделов токенов, типографики, расстояний, ролей компонентов и анимации в выбранном документе. Они не доказывают работу производственного приложения. В захвате остались текстовые подписи `var(--ink)`, поэтому разрешённые значения CSS и полная готовность гидратации не подтверждены. Клики, тёмная тема, узкие экраны и авторизация в этом проходе не проверялись. Скриншоты не запрашивались.

Это ограничение записано в [rea-replay-summary.json](../design/evidence/pace-jana/rea-replay-summary.json). Полный HTML, текст дерева доступности, шрифты и JavaScript не включены в репозиторий.

## Какие части дают пользу для HR

Ниже приведена оценка применимости. Это вывод исследования, а не результат теста готового JanaMen UI.

| Вариант | Плотный HR интерфейс | Кадровый процесс | Каталог из 30 курсов | Фирменная принадлежность | Повторное использование |
| --- | --- | --- | --- | --- | --- |
| Копирование маркетингового сайта Jana | Требует переработки структуры | На сайте нет подтверждённого кадрового процесса | Не является подтверждённым LMS | Сильный источник палитры и языка | Брать признаки бренда, не весь сайт |
| Pace без адаптации | Подходящая система повторяющихся контролов | Предметные состояния нужно связать с API | Есть полезные карточки и компоновки в публичном каталоге, но требуется проверка происхождения | Воспроизводит собственную идентичность Pace | Хороший кандидат после проверки версии и лицензий |
| Pace с Jana токенами и предметными композициями | Предпочтительный вариант | Отдельные роли для решения, возврата и ожидания | Рабочие фильтры, продолжение курса, история результата | Сохраняет узнаваемые признаки Jana | Повторно используются подтверждённые компоненты |
| Существующее предложение Base UI без Pace | Подходит для интерактивных элементов | Предметные композиции остаются нашими | Работает с тем же API | Фирменный слой нужен отдельно | Резервный путь для отсутствующих или неподтверждённых частей Pace |

Прочитанный комплект Pace включает поля, кнопки, карточки, переключатели, флажки, радиогруппы, вкладки, заглушки загрузки и разделители. Его 20 записей не являются полным набором кадрового портала. Например, наличие `dialog`, таблицы или календаря в каталоге сайта не подтверждает их присутствие в этом установочном манифесте.

Публичный `/workspace` показывает личный рабочий кабинет с задачами, фокус-сессией, заметками и локальным хранением. Его можно изучать как пример композиции. Он не доказывает серверную ролевую модель, согласование заявок или хранение персональных кадровых данных. JanaMen использует собственный backend и серверные права.

У компонентов одной роли должен быть один владелец. Если выбран проверенный Pace Dialog на Radix, не нужно параллельно строить второй Dialog на Base UI. Если в выбранном комплекте нужного элемента нет, следующий агент выбирает готовый поддерживаемый компонент и фиксирует решение. Переустановка всего frontend стека ради совпадения с сайтом Pace не требуется.

## Предлагаемое соответствие токенов

У Pace уже есть слой ролей. Для Jana полезно сохранить его API, чтобы компоненты не получали случайные локальные цвета. Предлагаемые значения ниже пока не внедрены.

| Токен Pace или роль Jana | Значение | Статус решения |
| --- | --- | --- |
| `--ink`, `--foreground` | `#12151A` и ссылка на `--ink` | Наблюдаемое значение Jana, предложенное применение |
| `--background` | `#F6F6F6` | Совпадает с наблюдаемой светлой основой обоих источников |
| `--card`, `--popover` | `#FFFFFF` | Предложение для рабочих блоков |
| `--muted-foreground` | `#5E5E60` | Значение Jana для читаемых подписей |
| `--brand` | `#008C00` | Отдельная фирменная роль |
| `--primary`, `--primary-text` | `#007A00` | Предложенный более тёмный цвет действия |
| `--primary-deep` | `#006B00` | Предложенный цвет нажатия и глубины. Не оставлять исходный индиго |
| `--primary-foreground` | `#FFFFFF` | Белый текст на предложенном цвете действия |
| `--ring` | Непрозрачный `#007A00` | Предложение. Рецепт полупрозрачного кольца нужно изменить или измерить отдельно |
| Фон выбранного элемента | `#F1FFF1` | Значение Jana, предложенная роль |
| Разделитель | `#DFDFDF` | Только структурная линия, не универсальная граница ввода |

Окрашивание одной переменной `--primary` оставит исходные оттенки в глубине кнопок, focus ring, диаграммах и производных ролях. Нужен полный проход по потребителям ролей. Цвет должен обозначать одну понятную вещь в конкретном контексте. Завершённый курс, выбранный пункт и согласованная заявка остаются разными состояниями с текстом и значком.

### Что показал расчёт контраста

Расчёт выполнен для непрозрачных объявленных пар в sRGB. Это проверка токенов. Финальный фон, наложения и состояние компонента потребуется проверить в браузере. Для обычного значимого текста W3C задаёт порог 4,5:1, для определённых нетекстовых элементов применяются отдельные требования. См. [Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) и [Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

| Пара | Расчёт | Решение |
| --- | ---: | --- |
| Белый на Jana `#008C00` | 4,420:1 | Ниже 4,5:1 для обычного текста |
| Белый на предложенном `#007A00` | 5,550:1 | Подходит для выбранной непрозрачной пары |
| `#12151A` на белом | 18,294:1 | Основной текст |
| `#5E5E60` на белом | 6,470:1 | Вторичный текст |
| `#898989` на белом | 3,498:1 | Не подходит для обычной значимой подписи |
| `#DFDFDF` на белом | 1,333:1 | Не считать достаточной границей, если она одна обозначает поле |

Значения показаны с округлением для чтения. Сравнение с порогом в evidence использует неокруглённый результат. Формула и пары находятся в [token-proposal.json](../design/evidence/pace-jana/token-proposal.json).

### Казахский текст требует отдельной проверки шрифта

Jana объявляет Inter и предварительно загружает Latin и Cyrillic файлы. Прочитанные `unicode-range` покрывают `ҰұІі`, но не покрывают `ӘәҒғҚқҢңӨөҮүҺһ`. Это проверка деклараций. Она не означает, что на сайте видны пустые квадраты: браузер может взять недостающие буквы из запасного шрифта.

Для JanaMen предлагается Inter с проверенным Cyrillic Extended набором и сохранённой лицензией. Нужен просмотр реально использованных шрифтов на всей строке `Ә Ғ Қ Ң Ө Ұ Ү Һ І`. Наличие файла `.woff2` само по себе не доказывает покрытие. В публичном CSS Pace присутствует объявление Inter Tight Cyrillic Extended, но для Jana выбранный шрифт и его загрузку нужно зафиксировать явно.

## Какие правила формы и движения перенести

В светлой теме публичного Pace объявлена основа радиуса `0.625rem` с производными коэффициентами. У Jana в HTML встречаются карточки с радиусом 20 px. Эти наблюдения дают диапазон для выбора, но не обязывают делать одинаково круглыми таблицы, меню и карточки курса.

Для первого прохода предлагаются компактные поля и таблицы, более свободные учебные карточки и отдельная ширина строки для чтения урока. Подписи и поля не уменьшаются ради помещения 30 курсов на одном экране. Каталог получает поиск, фильтры и понятное разделение назначенного и доступного обучения. Значимые числа используют табличные цифры.

Из оригинальных навыков Emil Kowalski и Jakub Krehel в решение перенесены следующие правила:

| Прочитанный навык | Конкретное следствие |
| --- | --- |
| `emil-design-eng` | Частые клавиатурные действия и просмотр строк не получают задерживающей анимации. Движение должно объяснять переход или подтверждать действие |
| `better-ui` | Состояния оставляют статический текстовый или графический признак. Переходы можно прервать. Hover не является единственным способом открыть действие |
| `better-colors` | Компоненты используют семантические роли. Фирменный зелёный отделён от цвета кнопки после измерения контраста |
| `better-typography` | Уроки получают читаемую строку, поля на мобильном экране учитывают размер текста, длинное значение доступно целиком |
| `explain-interface` | Декларации CSS, наблюдение DOM и предположение о поведении отмечены отдельно |
| `poteto-mode`, `how`, `technical-writing`, `unslop` | Решение имеет таблицу компромиссов, точные источники и явные нерешённые вопросы |

Система пружин Pace может быть полезна для появления диалога. Она не является причиной анимировать каждый фильтр и число. В этом исследовании движение Pace и режим reduced motion не проверены визуально. Нельзя записывать их как пройденные проверки JanaMen.

## Где возникнет отличие от обычного шаблона

Ценность REA состоит в проверке конкретных решений и происхождения компонентов. Сам факт запуска REA не является преимуществом для сотрудника. Следующие композиции превращают исследование в полезный интерфейс.

| Сценарий JanaMen | Что должен увидеть человек | Почему это заметно на демонстрации |
| --- | --- | --- |
| Возврат заявки | Причину, изменяемые данные, новую версию и кнопку повторной отправки из `allowed_actions` | Видно, что продукт умеет продолжать реальный процесс после ошибки |
| Согласование отпуска | Кто сейчас принимает решение и что ещё ожидается | Статус объясняет следующий шаг, а не только окрашивает бейдж |
| Доставка документа | Отдельное состояние отправки и подтверждение получателя | Решение HR не подменяется ложным сообщением о завершении интеграции |
| Остаток отпуска | Официальный остаток, резерв портала и подтверждённый учёт источником | Пользователь понимает происхождение числа и влияние своей заявки |
| Обучение | Следующий урок, срок, обязательность, предыдущая попытка и сохранённый результат | 30 курсов создают рабочий каталог с разными ситуациями |
| Ответ AI | Точный источник, действующую версию и понятный путь в HR при отсутствии основания | Доверие опирается на проверяемую информацию |

Эти композиции должны соответствовать [контрактам состояний](../design/state-and-data-contracts.md) и [OpenAPI](../../contracts/openapi.yaml). Это требования к будущему интерфейсу, а не заявление о готовых экранах.

Публичный Jana объясняет заказ через последовательные этапы и отслеживание. Для JanaMen полезна сама привычка показывать ход процесса. Людей не нужно изображать посылками, а этапы согласования не следует искусственно растягивать в линейную анимацию. Возврат, исправление и повторная отправка образуют ветвящийся процесс.

## Задание следующему Codex агенту

1. Получить доступную команде версию `yqecea/pace` и установить, какой коммит соответствует выбранному публичному демо. Зафиксировать пин.
2. Сопоставить экспортируемый комплект с каталогом. Отдельно проверить существование и поведение проверки использования компонентов.
3. Составить список импортируемых файлов с лицензиями и зависимостями. Исключить OxygenUI при текущем уведомлении. Разобрать AGPL snapshot отдельно, если он нужен.
4. Применить фирменные роли Jana и предложенные доступные производные цвета. Проверить реальные пары во всех состояниях.
5. Зафиксировать одну библиотеку для каждой интерактивной роли. Существующее предложение Base UI можно пересмотреть после проверки Pace, поскольку frontend ещё не реализован.
6. Собрать один полный кадровый маршрут с настоящим API, возвратом, конфликтом версии и интеграционным подтверждением. Затем распространить композиции на остальные сценарии.
7. Проверить каталог из 30 курсов, длинные русские и казахские тексты, доступность клавиатурой, 320 px, 200% масштаб, mobile touch и reduced motion.
8. Сохранить доказательства визуальных и поведенческих проверок. Не обозначать документированный или предполагаемый эффект как выполненный тест.

Итог исследования готов для выбора и реализации. Готовность самого frontend, визуальное качество будущих экранов и соответствие развёртывания Pace исходникам остаются открытыми проверками.
