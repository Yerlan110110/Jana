# Критерии качества и доказательства для frontend

Статус на 17 октября 2026 года: подготовлены спецификации и исследовательские доказательства. Интерфейс JanaMen этим агентом не реализован. Все проверки отрисованного JanaMen ниже ожидают выполнения frontend-агентом. Наличие этой таблицы не является сертификатом доступности или протоколом успешного теста.

Throughput checkpoint: n/a, read-only investigation. Запись относится к исследованию и документации этого агента. Код продукта и его измерения принадлежат соответствующим исполнительным задачам.

## Приёмка по шести направлениям

Все проверки Q01–Q18 имеют статус `pending frontend` на дату этого документа.

| ID | Направление | Принимаемый результат | Какое доказательство сохраняется |
| --- | --- | --- | --- |
| Q01 | Доступность | Весь маршрут от входа до решения или результата курса доступен с клавиатуры | Запись последовательности фокуса и снимки проблемных мест |
| Q02 | Доступность | У controls есть корректные native semantics и доступные названия. Диалог возвращает фокус | Результат проверки accessibility tree и ручного прохода |
| Q03 | Доступность | Ошибка поля связана с полем. Важное изменение объявляется без лишнего повторения | Проверка screen reader на формах и результате команды |
| Q04 | Доступность | При 200% zoom основной контент и действия остаются достижимыми | Снимки входа, формы, реестра, курса и AI-источника |
| Q05 | Доступность | При 320 CSS px отсутствует ненужная горизонтальная прокрутка страницы | Снимки заполненных экранов. Для действительно двумерной таблицы есть обоснованное поведение |
| Q06 | Доступность | Sticky-header и action bar не скрывают целиком элемент с фокусом | Keyboard-проход у краёв viewport |
| Q07 | Layout | В каждой карточке видны предмет, состояние и уместное действие. Длинный контент не ломает соседние элементы | Обычные и worst-case данные в одном реальном компоненте |
| Q08 | Layout | Пагинация, фильтр и возвращение из детали сохраняют контекст | Наблюдение на списке в несколько страниц |
| Q09 | Типографика | Длинные ФИО, названия юридических лиц и курсов читаются полностью через предусмотренный способ | RU и KZ fixtures без ручного укорачивания имён |
| Q10 | Типографика | Сумма, валюта, даты и проценты читаются однозначно. Важные числа не скрыты многоточием | Снимки крайних допустимых значений и отсутствующих полей |
| Q11 | Цвет | Статус понятен по тексту или символу без различения цвета | Проверка семантических элементов без цветовой подсказки |
| Q12 | Цвет | Реальные сочетания текста, controls и фокуса проверены на выбранный уровень WCAG | Измеренные пары цветов и их контекст, а не оценка на глаз |
| Q13 | UI | Pending не меняет размер кнопки скачком и не допускает случайное повторное действие | Наблюдение формы на задержанном ответе |
| Q14 | UI | Reduced motion сохраняет всю информацию. Высокочастотная работа не ждёт декоративного движения | Запись обычного и reduced-motion варианта |
| Q15 | Текст | Пустой реестр отличается от пустого фильтра и от ошибки запроса | Три реальные состояния одной страницы |
| Q16 | Текст | Ошибка сообщает действие для восстановления и не обещает неподтверждённый успех | 400, 409, provider failure и неопределённый результат команды |
| Q17 | Текст | Режим AI и синтетический статус регламента понятны в контексте | Ответ со ссылкой, extractive, отказ и недоступность провайдера |
| Q18 | Текст | KZ-перевод не заявлен там, где существует только русское содержание | Проверка language fallback и translated labels на реальных строках |

Основания для точных требований по доступности: [WCAG target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) и [focus not obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html). Для сенсорных основных действий проект использует цель 44 CSS px. Это удобство касания, а не утверждение, что WCAG AA требует 44 px без исключений.

## Адаптивная проверка

| Условие | Что проверяется | Недостаточное доказательство |
| --- | --- | --- |
| 320 px | Формы, источник, ошибки, навигация и отдельные строки реестра | Только пустая главная |
| 390 px | Экранная клавиатура, bottom controls, чтение урока и отправка теста | Только масштабирование desktop screenshot |
| 768 px | Перестройка реестров, фильтров и панелей деталей | Отсутствие ошибки сборки |
| 1280 и 1440 px | Плотность реестров, длина строк текста, видимость контекста решения | Большие пустые карточки с произвольными цифрами |
| 200% zoom | Доступность всех действий и важного содержания | Уменьшение текста ради помещения |
| Реальный телефон | Касания, safe area, высота при клавиатуре, прокрутка вложенного контента | Эмуляция считается дополнением, а не полным доказательством |

Не запрещайте zoom. Поля на мобильном устройстве должны оставаться читаемыми и не вызывать случайное изменение масштаба из-за слишком маленького текста. Hover-эффект не должен сохраняться после касания. Высота страницы учитывает динамический viewport и безопасные зоны. Ни один из этих критериев не обещает offline-работу.

## Сценарии, которые показывают качество продукта

| ID | Начальное состояние и действие | Наблюдаемый результат | Что доказывает |
| --- | --- | --- | --- |
| D01 | Сотрудник создаёт отпуск, руководитель возвращает его, сотрудник исправляет, руководитель и HR согласуют | У всех ролей одна текущая версия, сохранены предыдущая подача, причины и события | Целостность сквозного пути |
| D02 | Две разрешённые вкладки открыли одну заявку. В первой выполнено решение | Вторая не перезаписывает его. Интерфейс показывает 409 и актуальное состояние | Устойчивость к совместной работе |
| D03 | Руководитель открывает командную очередь и прямую ссылку на чужой отдел | Свои записи доступны, чужая не раскрывается ни списком, ни деталями, ни командой | Серверный RBAC и удобное объяснение границы |
| D04 | Сотрудник находит просроченное назначение среди 30 курсов, завершает материал, не сдаёт тест, повторяет успешно | Прогресс уроков сохраняется. Результаты попыток видны отдельно. История обновляется после подтверждения | Содержательная Academy |
| D05 | Сотрудник задаёт известный вопрос, открывает источник, затем неизвестный вопрос и создаёт HR-case | В ответе есть разрешённая ревизия. При отсутствии основания нет выдуманного правила. Case создаётся явным действием | Проверяемость AI Jana |
| D06 | HR публикует новую ревизию учебного материала или регламента | Исторические результаты и разрешённые старые ссылки имеют понятную версию | Воспроизводимость знаний |
| D07 | Одобренная заявка попадает в неуспешную mock-доставку, оператор повторяет доставку | Согласование сохранено. Повтор не создаёт дубликат внешней операции | Разделение бизнес-результата и интеграции |
| D08 | Пользователь проходит D01 или D04 с клавиатурой и на узком экране | Действия, ошибки и результат остаются доступны | Практическое качество интерфейса |

Эта программа демонстрации не сравнивает непроверенные слабости других участников. Она показывает собственные результаты, которые зритель может проверить. Живые действия выполняются на синтетических данных.

## Что сохранять в протоколе проверки

Для каждого сценария сохраняются commit, роль, dataset или seed revision, среда, шаги, ожидаемый результат и фактический результат. Нужны ссылки на снимки или журналы. Снимок final screen не доказывает промежуточные запреты или отсутствие дубликатов.

Производительность измеряется на реальной конфигурации. Время загрузки страницы, время API и время модельного ответа фиксируются отдельно. Целевые значения выбираются перед измерением и не объявляются достигнутыми по факту быстрой работы одного локального экрана.

Независимый review выполняет агент или человек, который не написал проверяемую часть. Авторская вычитка этой спецификации не считается независимым review. Родительский агент принимает исследовательский пакет. Проверки реализации продолжаются по основному HANDOFF.

## Формат записи результата

```text
Scenario: D04
Commit: <actual commit>
Dataset: <seed revision>
Role and scope: <test account and allowed entity>
Environment: <browser, viewport, database>
Expected: <observable behavior>
Observed: <actual behavior>
Evidence: <artifact or log>
Result: passed | failed | blocked | not_run
Remaining limitation: <concrete untested condition>
```

Этот шаблон предназначен для будущего выполнения. Пустые поля не заполняются правдоподобными результатами. Исправленная проверка выполняется снова на актуальном commit.
