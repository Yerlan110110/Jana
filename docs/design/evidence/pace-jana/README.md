# Evidence для Pace и Jana Post

Эти файлы сопровождают [решение о дизайн-системе](../../../research/pace-jana-design-system.md). Дата исследования: 17 октября 2026 года.

| Файл | Содержимое |
| --- | --- |
| [public-artifacts.json](public-artifacts.json) | URL, SHA-256 и размеры публичного HTML, CSS и объявленных ресурсов локального воспроизведения |
| [rea-replay-summary.json](rea-replay-summary.json) | Реальный результат REA 6.5.0, идентификатор evidence, среда, хеши DOM и дерева доступности, ограничения и закрытие собственных процессов |
| [source-provenance.json](source-provenance.json) | Идентичность выбранного Pace, проверенная ветка, расхождение каталога и установщика, результаты чтения лицензий |
| [token-proposal.json](token-proposal.json) | Наблюдаемые цвета Jana, предложенные семантические роли, измеренные пары контраста и проверка объявленных диапазонов шрифтов |

Успешный REA результат имеет authority `controlled-replay`. Он относится к публичной странице `/design`, воспроизведённой локально из скачанных байтов. Прямая навигация к vendor origin завершилась ошибкой до захвата начального состояния. Повтор неизменённой неудачной операции не выполнялся.

Проверка исходного репозитория использовала штатное соединение GitHub с доступом команды. Исходный код приватного Pace в этот репозиторий не переносился. Записаны только факты, нужные для выбора версии, совместимости и происхождения компонентов.

В Git не включены исходный HTML, полный DOM, полный текст доступности, сторонние JavaScript bundles, шрифты, изображения, скриншоты или приватные файлы. Сохранённые хеши позволяют связать наблюдения с конкретными байтами. Они не восстанавливают отсутствующий артефакт и не доказывают его доступность в будущем.

Проверка контраста относится к непрозрачным декларациям токенов. В ней нет заявления о визуальной доступности всех экранов источника или будущего JanaMen. Проверка казахских букв относится к CSS `unicode-range`, а не к отсутствию запасного шрифта в браузере.

Для повторения исследования новый агент получает публичный HTML с указанных URL, сверяет хеши, использует зафиксированную версию REA и сценарий из summary. Новое развёртывание может выдать другие байты. В этом случае требуется новый record, а не замена идентичности старого результата.
