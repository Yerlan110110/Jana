# Продолжить JanaMen в облаке. Только дизайн

Последнее поручение владельца от 18 октября. Продукт уже реализован. Следующий агент помогает поправить дизайн перед сдачей. Команда не занимается программированием и не читала ТЗ. Объясняйте словами пользователя, показывайте изменения в браузере и не добавляйте технические детали в защиту без необходимости.

## Начать с существующего проекта

1. Прочитайте `AGENTS.md`, `HANDOFF.md` и `docs/continuation-status.md`.
2. Прочитайте оригинальные задания в `docs/briefs/`. Это второй кейс, Digital HR. Отключённая сеть и разбор адресов относятся к первому кейсу.
3. Откройте `docs/defense/team-map.html`. Это автономная визуальная памятка с заданием, экранами, ответами жюри и сценарием на пять минут для двух человек.
4. Перед изменением UI прочитайте `docs/design/README.md`, `.agents/skills/fstack/SKILL.md`, `docs/research/continuation-reuse.md` и `docs/architecture/frontend.md`.

Сохраните Django, PostgreSQL, React, авторизацию, серверные права и сгенерированные API-типы. Не создавайте starter. Оба заявления, 30 базовых курсов, опубликованные редакции, отказ помощника и связь с HR уже работают. Не заменяйте эти сценарии статическими макетами.

## Запустить без файлов предыдущего компьютера

Нужны Git, Python 3 и Docker с Compose. Из свежего клона выполните:

```bash
python3 scripts/dev.py up
python3 scripts/dev.py credentials
```

Откройте `http://127.0.0.1:8080`. Логины `employee.demo`, `manager.demo`, `hr.demo`. Первый запуск создаёт локальные секреты и синтетические данные. Пароль показывает вторая команда. `.env`, база и секреты предыдущего компьютера не нужны. Полная инструкция находится в `README.md`.

Если Docker недоступен, используйте нативный запуск из README. Backend без браузера не доказывает работу изменённого интерфейса. Проверьте инструменты конкретной облачной сессии. Не заявляйте доступность Pstack, REA или браузера без фактического вызова.

## Сохранить смысл продукта

Сотрудник понимает следующее действие, ответственную роль и подтверждённый результат. Сначала покажите владельцу существующие экраны. Выясняйте его визуальные предпочтения по конкретным вариантам.

Сохраняйте серверную очередь, историю подач, текст при конфликте версий, безопасный повтор, прогресс обучения и доступ к источникам. Согласование, доставка и кадровый учёт остаются разными фактами. Помощник находит выдержки. Реальный LLM-провайдер, 1С и Documentolog не проверены.

## Проверить и сохранить изменения

Используйте `.agents/skills/verify-janamen/SKILL.md` и `.github/workflows/`. Проверьте затронутые пути ролей в настоящем браузере. Проверьте узкий экран, клавиатуру, видимый фокус, масштаб и ошибки.

Последний завершённый CI до передачи относится к `5bd6856`. Полная приёмка всех состояний остаётся открытой. R3 является третьим раундом из трёх; передача не открывает R4 и не отменяет COV1. Новый дизайн требует новой проверки.

Сырые локальные трассы в `.artifacts/` не входят в Git. Используйте опубликованные отчёты, GitHub Actions и сценарии в `tests/`. Не считайте отсутствующие трассы просмотренными.

Владелец разрешил содержательные коммиты и push в `Yerlan110110/Jana`. Перед push выполните CI. Не делайте force-push. Не публикуйте пароли, токены или настоящие кадровые данные.
