# JanaMen — передача следующему агенту

## Цель и решения владельца

Репозиторий: **https://github.com/Yerlan110110/Jana**. Трек: **Digital HR**, личный кабинет сотрудника JanaMen.

Владелец просит содержательный продукт и качество выше сокращения работы ради предполагаемой нехватки времени. Это правило относится к данному хакатону. Не заменять 30 курсов одним, разнообразную организацию одной персоной или рабочий процесс имитацией на клиенте. Отпуска и зарплатные авансы входят в выбранный объём.

Backend, исследования, архитектура, данные и API — текущая поставка. **В последнем указании пользователь передал Codex полную дальнейшую ответственность: архитектура, backend, frontend, визуальный дизайн, UX flow, проверки и защита.** Он разрешил автономно заполнять и публиковать этот репозиторий, использовать максимум параллельных агентов и просит стремиться к первому месту. Решение жюри не гарантируется; качество доказывается работающими сценариями. Готовый стартовый текст: [CODEX_START.md](CODEX_START.md).

Pstack и оригинальные навыки Emil Kowalski/Jakub Krehel обязательны для применимых задач. REA применяется к подходящим артефактам и runtime-вопросам. Обычный анализ полного исходного кода не переименовывается в REA. Пользователь не просил переносить медицинский домен или закрытый код MIS Pro.

| Seed сотрудников и заявок | 58 сотрудников, 126 заявлений, два юрлица; полный повтор сохраняет изменения; медленный запрос свежей PostgreSQL исправлен |

| Workbench | Работает `/api/v1/workbench/`; области, сводки и доступные действия проверены через API и реальные HTTP-реестры |

Не суммируйте тесты из разных worktree как число уникальных тестов: в каждом прогоне может повторяться core suite. Используйте финальный объединённый отчёт.

Два HTTP-прогона содержат по 807 успешных проверок, включая повторные проверки транспорта и формы ответа; это не 807 отдельных бизнес-сценариев. Они добавляют собственные синтетические записи. Фиксированные количества seed относятся к [baseline до этих прогонов](docs/verification/evidence/demo-baseline.json), а текущие UI-счётчики всегда берутся из API.

## Как начать исполнение

Полные команды и аккаунты находятся в [README](README.md). Основной путь:

```bash
python3 scripts/dev.py up
python3 scripts/dev.py credentials
```

Команда генерирует локальные секреты, запускает PostgreSQL, release, API и worker. Есть нативный путь через `uv`, если Docker недоступен. Не переносите временные DSN, БД и runtime-файлы из среды предыдущего агента в публичный код.

Проверка контракта из корня:

```bash
npm ci --ignore-scripts --no-audit --no-fund
npm run contracts:check
```

Проверка backend на PostgreSQL:

```bash
python3 scripts/dev.py test-postgres
```

Для независимого HTTP-прогона с реальными cookie используйте [готовый runner](scripts/verification/README.md). Он создаёт собственные синтетические заявления и курс, сохраняет безопасный отчёт и не сбрасывает набор данных.

SQLite недостаточно для проверки row locks и конкурентного согласования. Поднимать PostgreSQL заново ради исследования не нужно, если уже есть безопасная выделенная тестовая БД.

## Не потерять предметные правила

| Правило | Как его сохранить во frontend |
| --- | --- |
| Кадровые факты принадлежат 1С | Профиль не содержит форму произвольной правки баланса, руководителя и должности |
| Проекция отличается от официального остатка | Показывать источник, дату и объяснимые отдельные значения |
| Отправленная версия неизменяема | История и revision detail не заменяются текущим черновиком |
| Команда проверяет роль, состояние и версию | Использовать `allowed_actions`, `expected_version`, корректно обрабатывать 409 |
| Один intent имеет один Idempotency-Key | Повтор после сетевого обрыва не создаёт новую заявку или попытку |
| Самосогласование запрещено | Демо HR собственной заявки проходит через второго HR |
| Курс и назначение имеют разные жизненные циклы | Архив курса не удаляет историю; due date не равна доступности |
| Оценка и завершение вычисляются сервером | Не отправлять клиентское `score` или процент как итог |
| Цитата разрешается сервером | Отозванный источник не восстанавливается из browser cache |
| Согласование не равно исполнению | Не писать «выплачено» или «подписано» по статусу `approved` |
| Интеграционный retry не меняет человеческое решение | Ошибка доставки показывается отдельным состоянием |
| AI не принимает кадровых решений | В интерфейсе нет автоматического approve по совету модели |

Текущая политика отпуска — явно синтетический подсчёт календарных дней включительно. Реальный порядок Jana Post и юридическую формулу ещё нужно подтвердить у организатора. Не выводить их из созданного учебного контента.

При изменении назначенного руководителя ожидающее заявление не получает нового согласующего автоматически. Нужно следовать фактическим `allowed_actions` и принятой политике отмены/повторной отправки. Отмена уже согласованного заявления требует отдельной предметной политики; удаление истории недопустимо.

## Данные для дизайна

Основной аккаунт `employee.demo` — Дана Нұрланқызы Әбдірахманова. Её руководитель — `manager.demo`; HR — `hr.demo`. Есть второй HR, другая команда, второе юрлицо и новичок. Пароли локальные, генерируемые; они не зашиты в frontend.

Использовать [curriculum-and-fixtures.md](docs/design/curriculum-and-fixtures.md): 30 тематических курсов, обязательное и рекомендованное обучение, разные стадии, повторные попытки, сроки. Сверять канонические коды курса с seed, а не заводить отдельный набор случайных карточек.

Проверять наполненные и пустые состояния одним компонентом. В реестре должны работать фильтры, возврат из детали и пагинация. Все числовые показатели имеют определение и область данных. Пользователю не показываются придуманные тренды, ROI и метрики использования.

## Последующие параллельные задачи

| Исполнитель | Изолированная ответственность | Проверяемый результат |
| --- | --- | --- |
| UI architecture / shell | Route map, session/query boundary, локализация, primitives | Вход, выход, cache isolation и навигация с клавиатуры |
| Requests / people UI | Профиль, реестры, форма, решения, история | Полный маршрут двух типов заявления и конфликт версий |
| Academy UI | Каталог, назначения, player, quiz, результаты, HR authoring | 30 курсов, сохранённый прогресс, успех/ошибка/повтор |
| Knowledge / evidence UI | Вопросы, режимы, цитаты, HR cases, публикация | Источник, отказ, отзыв доступа и человеческий ответ |
| Independent verification | Browser journeys, role isolation, narrow layouts, deployment | Воспроизводимый отчёт с фактическими доказательствами |

Выделять отдельный worktree каждому автору. Общий router, дизайн-токены, lock и generated contract меняет один интегратор. Авторы не заменяют независимого ревьюера своей самооценкой. Число одновременно работающих агентов определяется доступными слотами среды; задачи продолжаются следующими волнами.

## Какие инструменты дадут следующий прирост

**Настоящий browser control и frontend runtime.** Реализовать и пройти восемь demo flows из design quality gates на employee/manager/HR. Проверить cookie/CSRF, смену аккаунтов, deep links, неизвестный сетевой результат, 409, reduced motion, zoom, mobile и screen reader. В этой поставке отсутствие UI не закрывается backend-тестами.

**Ключ и выбранная модель.** Запустить provider-backed AI eval, включая RU/KZ, перефразирования, закрытые документы, неоднозначность, prompt injection и outage. Опубликованный fixture-набор служил настройке и не считается независимой оценкой качества. Добавить отдельный held-out набор. В текущем generated mode модель выбирает полные предложения, а сервер проверяет source-bound claims. Свободная генерация требует отдельной стратегии проверки поддержки каждого утверждения.

**Docker daemon / доступный CI.** Свериться с [финальным отчётом](docs/verification/final.md): статус удалённого CI фиксируется отдельно от нативного прогона. Если контейнерный gate остаётся открытым, выполнить сборку, чистую миграцию, seed, health и worker, затем PostgreSQL suite. Один `compose config` не закрывает этот gate.

**Разрешённые профессиональные демо.** Для дальнейшего REA исследовать доступный авторизованный demo instance или публичные shipped assets. Сохранить точные URL, версии, hashes, сценарии и Evidence IDs. Live-навигации в текущей REA-среде завершались до capture; успешный replay статьи не доказывает UX настоящей платформы. Не повторять неизменный неудачный запуск бесконечно.

**Pace и Jana.** [Отдельное исследование](docs/research/pace-jana-design-system.md) содержит найденное расхождение публичного каталога и исходников `yqecea/pace`, проверенные лицензии подмножеств, реальные CSS-декларации Jana и карту предложенных tokens. Контролируемый replay `/design` сохранил DOM/AX и версии инструментов. Установка kit, computed styles, interactions и узкие экраны требуют проверки Codex. Предпочтительный путь — проверенные компоненты Pace, фирменные роли Jana и предметные HR-композиции.

**Подтверждённые API организаторов.** Реальные 1С/Documentolog требуют согласованной схемы и доступов. Нормализованный mock не выдаётся за их официальный wire format. Проверить порядок/коррекцию source revisions и корреляцию отпусков, уже отражённых в остатке, отдельно от квитанции Documentolog.

## Применение Pstack и Fstack

Следуйте [Codex setup](docs/tooling/codex-setup.md), затем читайте применимые исходные skills. Pstack повлиял на сравнение альтернатив, модель данных, транзакционные команды и независимую проверку. Emil/Jakub — на состав состояний, reuse primitives, доступность, typography и доказательную приёмку. Установка 94 skills не означает, что нужно запускать нерелевантные Swift, 3D и маркетинговые workflows.

REA-зависимости изолированы от приложения. В upstream-файлах сохранены лицензии и digests. Изменения skills должны быть закоммичены; после них запускается integrity verifier. Если skills не обнаружены конкретным Codex-клиентом, установите причину по setup, а не объявляйте успех по наличию папки.

## Как принимать результат следующей части

У каждого завершённого сценария должно быть: действующий API, реальный UI, сохранённое состояние, доказанный отказ чужой роли, корректное восстановление после ошибки и наблюдение в браузере. Сохраните фактическую команду, commit, окружение и ограничения проверки.

Для защиты объяснять преимущество через демонстрируемое поведение: понятное следующее действие, история, сохранённый учебный результат, проверяемый источник и восстановление интеграции. Работы остальных участников не изучены; обещание уникальности или победы не является исследовательским выводом.
